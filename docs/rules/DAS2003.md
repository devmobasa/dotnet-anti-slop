# DAS2003: Do not capture a scoped dependency in a singleton

**Category:** Dependency Injection

**Default severity:** error
**Signal confidence:** medium

## Rule

Redesign the lifetime boundary or create an explicit scope at operation time.

## Why

A singleton that holds a scoped service effectively promotes it to the root lifetime and can use disposed or non-thread-safe state.

## Noncompliant

```csharp
services.AddScoped<RequestStore>(); services.AddSingleton<ReportCache>(); // ReportCache(RequestStore store)
```

## Compliant

```csharp
services.AddSingleton<ReportCache>(); // ReportCache(IServiceScopeFactory scopes), resolve per operation
```

## Detection

Collects scoped registrations per compilation and checks singleton implementation constructors for those scoped types or a `DbContext`.

## Boundaries

Only registrations visible in the same compilation and constructor injection are modeled. Factory-created scopes require review.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2003.severity = error
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

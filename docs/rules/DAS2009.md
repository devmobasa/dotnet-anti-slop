# DAS2009: Validate bound options at startup

**Category:** Configuration
**Default severity:** warning
**Signal confidence:** medium

## Rule

Call `ValidateOnStart()` after binding an `OptionsBuilder<TOptions>`, or begin
with `AddOptionsWithValidateOnStart<TOptions>()`.

## Why

Without startup validation, invalid configuration can survive deployment and
fail only when the affected options are first resolved. Startup validation
makes configuration failure immediate and repeatable.

## Noncompliant

```csharp
services.AddOptions<MailOptions>()
    .BindConfiguration("Mail");
```

## Compliant

```csharp
services.AddOptions<MailOptions>()
    .BindConfiguration("Mail")
    .ValidateDataAnnotations()
    .ValidateOnStart();
```

## Detection

Reports resolved Microsoft options `Bind` and `BindConfiguration` calls that
return `OptionsBuilder<TOptions>` without startup validation. Fluent validation,
a later unconditional `ValidateOnStart()` call on the same local or named
builder, and `AddOptionsWithValidateOnStart<TOptions>()` are recognized. A local
initialized by `AddOptionsWithValidateOnStart<TOptions>()` retains that
provenance unless it is reassigned on the immediate execution path before
binding. Later validation is matched to the same unmodified builder, service
receiver, options type, and option-name value. Guaranteed validation in a local
initializer is recognized, as are assignments in directly invoked local
functions and local delegates.

## Boundaries

The analyzer intentionally does not report `Configure<TOptions>` or custom
binding helpers. It performs local syntax and symbol analysis, not whole-program
control-flow analysis. Validation hidden in another method, lambda, local
function, conditional branch, or flow after a possible early exit is not
treated as guaranteed startup validation. Matching property accesses on the
same receiver are treated as stable unless an intervening assignment is found.
Method calls are not assumed to return the same service collection or option
name; store their result in a local when the identity should be shared.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2009.severity = warning
```

Suppress an individual binding only when another startup path proves equivalent
validation, and record that reason beside the suppression.

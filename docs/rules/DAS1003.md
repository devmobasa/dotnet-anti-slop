# DAS1003: Avoid async void outside event handlers

**Category:** Async

**Default severity:** error
**Signal confidence:** high

## Rule

Return Task or ValueTask so callers can await completion and observe exceptions.

## Why

Exceptions from async void cannot be observed through a returned task, and callers cannot compose or cancel the operation.

## Noncompliant

```csharp
public async void RefreshAsync() => await RefreshCoreAsync();
```

## Compliant

```csharp
public async Task RefreshAsync(CancellationToken cancellationToken) => await RefreshCoreAsync(cancellationToken);
```

## Detection

Reports async methods/local functions returning `void`; conventional `(object, EventArgs)` handlers and framework test methods are handled separately.

## Boundaries

True event handlers are allowed. UI frameworks with non-standard event signatures may need a narrow suppression.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS1003.severity = error
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

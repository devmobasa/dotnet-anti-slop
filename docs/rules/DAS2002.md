# DAS2002: Do not register DbContext as a singleton

**Category:** Dependency Injection

**Default severity:** error
**Signal confidence:** high

## Rule

Use AddDbContext or a scoped registration for DbContext.

## Why

DbContext is not thread-safe and is designed around a short unit-of-work lifetime.

## Noncompliant

```csharp
services.AddSingleton<AppDbContext>();
```

## Compliant

```csharp
services.AddDbContext<AppDbContext>(options => options.UseSqlServer(connectionString));
```

## Detection

Inspects singleton registration type arguments, `typeof` arguments, and factory return types for `DbContext` derivation.

## Boundaries

A factory or pooled context is still not a singleton `DbContext` instance. Register the factory/pool through the EF APIs.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2002.severity = error
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

# DAS2008: Do not cache IHttpContextAccessor.HttpContext

**Category:** ASP.NET Core
**Default severity:** warning
**Signal confidence:** high

## Rule

Store `IHttpContextAccessor`, not the value of its `HttpContext` property, and
read the current context only when it is needed.

## Why

`HttpContext` is request-specific. A value captured during construction can be
`null`, and a value retained in an object can refer to a request that has
already completed when it is used later.

## Noncompliant

```csharp
public Handler(IHttpContextAccessor accessor)
{
    _context = accessor.HttpContext;
}
```

## Compliant

```csharp
public Handler(IHttpContextAccessor accessor)
{
    _accessor = accessor;
}

private HttpContext? CurrentContext => _accessor.HttpContext;
```

## Detection

Reports an `IHttpContextAccessor.HttpContext` property read assigned to a field
or property. Assigning the accessor itself is allowed.

## Boundaries

Local variables are not reported because a short-lived snapshot within the
current operation can be appropriate. The rule does not track a context passed
through helper methods or stored indirectly in another object.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2008.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

# DAS3008: Bound request-driven query materialization

**Category:** EF Core

**Default severity:** suggestion
**Signal confidence:** medium

## Rule

Page, cap, stream, or aggregate entity collections returned from request handlers.

## Why

An unbounded ToListAsync can turn data growth into high latency, large allocations, and response failures.

## Noncompliant

```csharp
app.MapGet("/orders", async (AppDbContext db, CancellationToken ct) => await db.Orders.AsNoTracking().ToListAsync(ct));
```

## Compliant

```csharp
app.MapGet("/orders", async (int skip, AppDbContext db, CancellationToken ct) => await db.Orders.AsNoTracking().OrderBy(x => x.Id).Skip(skip).Take(100).ToListAsync(ct));
```

## Detection

Reports `ToList[Async]`/`ToArray[Async]` over EF sources in GET/HEAD handlers when no visible `Take` or single-row terminal bounds the result.

## Boundaries

A naturally tiny table may be acceptable, but request-facing bounds make the contract resilient to future data growth.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS3008.severity = suggestion
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

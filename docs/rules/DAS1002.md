# DAS1002: Do not call Thread.Sleep from asynchronous code

**Category:** Async

**Default severity:** warning
**Signal confidence:** high

## Rule

Use an awaited delay or another non-blocking coordination primitive.

## Why

Thread.Sleep occupies the current worker for the full delay. Task.Delay yields the worker and supports cancellation.

## Noncompliant

```csharp
Thread.Sleep(250);
```

## Compliant

```csharp
await Task.Delay(TimeSpan.FromMilliseconds(250), cancellationToken);
```

## Detection

Reports the real `System.Threading.Thread.Sleep` symbol only when it appears in an async callable or resolved ASP.NET Core request handler.

## Boundaries

Synchronous console utilities may intentionally sleep. The rule is limited to async and request contexts.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS1002.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

# DAS1001: Avoid sync-over-async

**Category:** Async

**Default severity:** warning
**Signal confidence:** high

## Rule

Await asynchronous work instead of blocking with Result, Wait, or GetAwaiter().GetResult().

## Why

Blocking a Task ties up a thread and can starve the thread pool under load. In request code it also defeats end-to-end asynchrony.

## Noncompliant

```csharp
var customer = GetCustomerAsync(id).Result;
```

## Compliant

```csharp
var customer = await GetCustomerAsync(id, cancellationToken);
```

## Detection

Reports `Task`/`ValueTask` `.Result`, `Task.Wait()`, and `GetAwaiter().GetResult()` when the resolved symbol is task-like.

## Boundaries

A deliberate synchronous boundary may be unavoidable in legacy integration code. Suppress at the boundary, never throughout the call graph.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS1001.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

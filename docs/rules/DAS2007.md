# DAS2007: Do not fire-and-forget request work

**Category:** ASP.NET Core

**Default severity:** error
**Signal confidence:** high

## Rule

Await request work or enqueue a durable/background operation that owns its scope.

## Why

Unobserved request tasks can outlive scoped services, lose exceptions, and disappear when the process shuts down.

## Noncompliant

```csharp
app.MapPost("/jobs", (Job job) => { _ = processor.RunAsync(job); return Results.Accepted(); });
```

## Compliant

```csharp
app.MapPost("/jobs", async (Job job, CancellationToken ct) => { await queue.EnqueueAsync(job, ct); return Results.Accepted(); });
```

## Detection

Reports task-returning invocations used as bare statements or assigned to discard inside a resolved request handler.

## Boundaries

Framework lifecycle callbacks and explicit background queues are not bare task invocations and should express ownership in their API.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2007.severity = error
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

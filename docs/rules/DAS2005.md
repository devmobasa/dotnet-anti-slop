# DAS2005: Do not construct HttpClient per request

**Category:** HTTP

**Default severity:** warning
**Signal confidence:** high

## Rule

Inject HttpClient, use a typed client, or use IHttpClientFactory.

## Why

Per-operation clients lose handler pooling and can cause connection churn or socket exhaustion.

## Noncompliant

```csharp
var client = new HttpClient(); return await client.GetStringAsync(uri);
```

## Compliant

```csharp
public OrdersClient(HttpClient client) { _client = client; }
```

## Detection

Reports the real `System.Net.Http.HttpClient` constructor only inside a resolved request-handler context.

## Boundaries

A long-lived static client in non-request code is not reported. Typed clients are normally clearer in ASP.NET Core.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2005.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

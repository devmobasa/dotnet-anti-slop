# DAS3002: Do not re-enable tracking on a read-only query

**Category:** EF Core

**Default severity:** warning
**Signal confidence:** high

## Rule

Remove AsTracking from read-only query chains, especially after AsNoTracking.

## Why

AsTracking overrides no-tracking behavior and reintroduces state management costs.

## Noncompliant

```csharp
db.Orders.AsNoTracking().AsTracking().ToListAsync(ct);
```

## Compliant

```csharp
db.Orders.AsNoTracking().ToListAsync(ct);
```

## Detection

Reports resolved EF Core `AsTracking` in a read-only context or after a no-tracking operator.

## Boundaries

A later tracking operator intentionally changes query semantics. Keep it only when the returned entities will be updated.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS3002.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

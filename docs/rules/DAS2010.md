# DAS2010: Observe EventCallback.InvokeAsync tasks

**Category:** Blazor
**Default severity:** warning
**Signal confidence:** high

## Rule

Await, return, store for deliberate observation, or compose the task returned
by `EventCallback.InvokeAsync`. Do not invoke it as a bare statement or assign
it to a discard.

## Why

An event callback can run asynchronous parent-component work. Dropping its task
allows the initiating component to continue before that work completes and
hides callback failures from the current operation.

## Noncompliant

```csharp
private void NotifyChanged(int value)
{
    ValueChanged.InvokeAsync(value);
}
```

## Compliant

```csharp
private async Task NotifyChangedAsync(int value)
{
    await ValueChanged.InvokeAsync(value);
}
```

A task-returning Razor callback can return the task directly:

```csharp
Func<Task> handler = () => ValueChanged.InvokeAsync(value);
```

## Detection

Reports a resolved `Microsoft.AspNetCore.Components.EventCallback` or
`EventCallback<TValue>` `InvokeAsync` call whose invocation operation is a bare
expression statement or the value of a discard assignment. A dedicated Blazor
pass inspects generated C# only at locations mapped back to authored `.razor`
source from a generated `.g.cs` tree. Other generated trees are ignored.

## Boundaries

Awaited, returned, assigned, argument-composed, and task-returning lambda uses
are allowed. Conditional access is unwrapped before determining whether the
result is dropped. The analyzer does not trace a task that is stored and later
dropped, or callbacks hidden behind custom wrappers.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2010.severity = warning
```

Prefer changing the containing handler to return `Task` over suppressing the
diagnostic.

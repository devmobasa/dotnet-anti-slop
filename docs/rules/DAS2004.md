# DAS2004: Request handlers should accept CancellationToken

**Category:** ASP.NET Core

**Default severity:** warning
**Signal confidence:** high

## Rule

Accept the request-aborted token in asynchronous controllers, minimal API handlers, and middleware delegates.

## Why

ASP.NET Core binds CancellationToken to HttpContext.RequestAborted, allowing disconnected requests to stop downstream work.

## Noncompliant

```csharp
app.MapGet("/orders", async () => await service.ListAsync());
```

## Compliant

```csharp
app.MapGet("/orders", async (CancellationToken ct) => await service.ListAsync(ct));
```

## Detection

Recognizes controller actions and resolved minimal-API/middleware mapping symbols. Reports async handlers with cancellable work, no token parameter, and no explicit `RequestAborted` use.

## Boundaries

Handlers with no asynchronous/cancellable work are ignored. Explicit `HttpContext.RequestAborted` use is accepted.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2004.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

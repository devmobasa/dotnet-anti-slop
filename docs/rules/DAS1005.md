# DAS1005: Do not replace an available token with CancellationToken.None

**Category:** Async

**Default severity:** warning
**Signal confidence:** high

## Rule

Use the token already available in the current operation.

## Why

CancellationToken.None silently breaks cancellation propagation and wastes work after abandonment.

## Noncompliant

```csharp
await client.SendAsync(request, CancellationToken.None);
```

## Compliant

```csharp
await client.SendAsync(request, cancellationToken);
```

## Detection

Reports `CancellationToken.None` or `default(CancellationToken)` passed while a token parameter is available in the current callable.

## Boundaries

A detached operation can intentionally ignore caller cancellation, but it must own its lifetime and resources.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS1005.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

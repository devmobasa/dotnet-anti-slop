# DAS2001: Do not build a nested service provider

**Category:** ASP.NET Core

**Default severity:** error
**Signal confidence:** high

## Rule

Let the host build and own the application service provider.

## Why

BuildServiceProvider during registration creates duplicate singleton graphs, broken scopes, and disposal leaks.

## Noncompliant

```csharp
services.AddSingleton(services.BuildServiceProvider().GetRequiredService<Clock>());
```

## Compliant

```csharp
services.AddSingleton<Clock>();
```

## Detection

Reports the resolved Microsoft dependency-injection `BuildServiceProvider` extension, not methods that only share its name.

## Boundaries

A separate provider in isolated design-time tooling can be intentional. Do not use one in the application registration graph.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS2001.severity = error
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

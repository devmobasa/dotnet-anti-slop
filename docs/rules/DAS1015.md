# DAS1015: Do not silently swallow exceptions

**Category:** Reliability
**Default severity:** warning
**Signal confidence:** high

## Rule

Do not leave a catch block empty. Handle or propagate the failure. If a
specific exception is expected and intentionally ignored, document that reason
inside the catch block.

## Why

An empty catch hides failed work from callers and operators. The program can
continue with incomplete state while the original cause is lost.

## Noncompliant

```csharp
try
{
    Save();
}
catch
{
}
```

## Compliant

```csharp
try
{
    Save();
}
catch (OperationCanceledException)
{
    // Expected after the caller cancels this best-effort refresh.
}
```

Handling, logging at an actionable boundary, or rethrowing also satisfies the
rule.

## Detection

Reports an empty catch block unless the catch names a type derived from
`System.Exception`, is narrower than `System.Exception`, and contains a local
comment documenting the intentional swallow.

## Boundaries

The analyzer does not judge whether a non-empty handler is sufficient. It also
does not infer justification from comments outside the catch block.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS1015.severity = warning
```

Prefer a narrow exception and a local design reason over globally disabling the
rule.

# DAS1014: Do not convert async lambdas to void-returning delegates

**Category:** Async
**Default severity:** error
**Signal confidence:** high

## Rule

Use a task-returning delegate for asynchronous lambda expressions and
anonymous methods, except at a direct event-handler boundary.

## Why

An async lambda converted to a void-returning delegate has `async void`
semantics. Its caller cannot await completion, compose it with other work, or
observe failures through a returned task.

## Noncompliant

```csharp
Action work = async () => await ProcessAsync();
```

## Compliant

```csharp
Func<Task> work = async () => await ProcessAsync();
```

## Detection

Reports an `async` lambda or anonymous method whose resolved delegate invoke
method returns `void`.

## Boundaries

Direct event subscription is allowed because event handlers are the intended
`async void` boundary. The analyzer does not infer that a custom registration
method ultimately stores a delegate as an event handler.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS1014.severity = error
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

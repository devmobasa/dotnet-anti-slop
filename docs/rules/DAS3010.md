# DAS3010: Do not run parallel operations on one DbContext

**Category:** EF Core

**Default severity:** error
**Signal confidence:** high

## Rule

Await each operation before starting the next, or give concurrent operations separate scopes and DbContext instances.

## Why

DbContext does not support multiple parallel operations and can corrupt unit-of-work assumptions.

## Noncompliant

```csharp
await Task.WhenAll(db.Orders.ToListAsync(ct), db.Customers.ToListAsync(ct));
```

## Compliant

```csharp
var orders = await db.Orders.ToListAsync(ct); var customers = await db.Customers.ToListAsync(ct);
```

## Detection

Within an inline `Task.WhenAll`, resolves EF operations back to their `DbContext` symbol and reports repeated use of the same instance.

## Boundaries

Separate context instances may run concurrently. The local analysis covers inline task fan-out, not tasks stored earlier.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS3010.severity = error
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

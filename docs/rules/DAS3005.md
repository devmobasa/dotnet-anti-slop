# DAS3005: Avoid database queries inside loops

**Category:** EF Core

**Default severity:** warning
**Signal confidence:** high

## Rule

Batch keys, join, project, or prefetch instead of issuing one query per iteration.

## Why

A query in a loop commonly creates an N+1 round-trip pattern whose latency grows with input size.

## Noncompliant

```csharp
foreach (var id in ids) orders.Add(await db.Orders.SingleAsync(x => x.Id == id, ct));
```

## Compliant

```csharp
var orders = await db.Orders.Where(x => ids.Contains(x.Id)).ToListAsync(ct);
```

## Detection

Reports resolved EF/LINQ query terminal operations over a `DbSet` beneath a loop.

## Boundaries

Queries in loops are sometimes bounded and intentional, but batching almost always scales better. The analyzer cannot inspect query plans.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS3005.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

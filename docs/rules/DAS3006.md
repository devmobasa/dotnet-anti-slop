# DAS3006: Keep filtering and projection on the server

**Category:** EF Core

**Default severity:** warning
**Signal confidence:** high

## Rule

Apply Where, Select, ordering, and paging before materialization.

## Why

Materializing before shaping transfers extra rows and columns and spends CPU and memory in the application.

## Noncompliant

```csharp
await db.Orders.ToListAsync(ct).ContinueWith(t => t.Result.Where(IsOpen));
```

## Compliant

```csharp
await db.Orders.Where(x => x.Status == Status.Open).Select(x => new OrderDto(x.Id)).ToListAsync(ct);
```

## Detection

Reports LINQ shaping calls whose receiver already contains EF materialization or `AsEnumerable`.

## Boundaries

Some operations cannot translate. Make the client boundary explicit, cap the server result first, and suppress locally.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS3006.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

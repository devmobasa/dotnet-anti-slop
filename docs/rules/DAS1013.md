# DAS1013: Run TaskCompletionSource continuations asynchronously

**Category:** Async
**Default severity:** warning
**Signal confidence:** high

## Rule

Create `TaskCompletionSource` with
`TaskCreationOptions.RunContinuationsAsynchronously`.

## Why

Completing a task source can otherwise run an awaiting continuation inline on
the producer's thread. That couples the producer to arbitrary consumer work
and can cause lock inversions, re-entrancy, or thread starvation.

## Noncompliant

```csharp
var completion = new TaskCompletionSource<Result>();
```

## Compliant

```csharp
var completion = new TaskCompletionSource<Result>(
    TaskCreationOptions.RunContinuationsAsynchronously);
```

## Detection

Reports generic and non-generic `TaskCompletionSource` construction when the
bound constructor has no `TaskCreationOptions` argument, or when a
compile-time-constant options argument omits
`RunContinuationsAsynchronously`.

## Boundaries

A non-constant options value is not reported because the analyzer cannot prove
which flags it contains. The rule does not trace factory methods that create a
task source elsewhere.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS1013.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.

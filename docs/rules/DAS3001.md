# DAS3001: Use no-tracking for read-only entity queries

**Category:** EF Core

**Default severity:** warning
**Signal confidence:** medium

## Rule

Add AsNoTracking or configure no-tracking behavior when entities are materialized only for reading.

## Why

Change tracking adds identity-map work and retained state that read-only paths do not need.

## Noncompliant

```csharp
return await db.Orders.Where(x => x.CustomerId == id).ToListAsync(ct);
```

## Compliant

```csharp
return await db.Orders.AsNoTracking().Where(x => x.CustomerId == id).ToListAsync(ct);
```

## Detection

On read-only method/GET contexts, follows the query receiver to a `DbSet<TEntity>`, verifies entity materialization, and ignores scalar/DTO projections and existing no-tracking calls.

## Boundaries

Tracking is required for mutation, relationship fix-up, or identity semantics. The analyzer limits itself to recognizable read-only contexts.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.DAS3001.severity = warning
```

Use `none` only after replacing the policy with an equivalent architectural or
test-enforced control. Prefer a line- or member-level suppression for a
documented exception.
